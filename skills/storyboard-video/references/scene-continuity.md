# 场景连续性与并行

## 先画依赖关系

镜头是否能并行，由共享主体和输入依赖决定，不由镜号决定。

- **强依赖**：同一主体连续形变、摄影机连续运动、必须继承前镜尾帧。依赖部分顺序制作。
- **接口依赖**：主体场景可独立完成，只等待前镜尾帧决定入场位置或桥接参数。主体、静态帧和内部动画先并行，最后接桥。
- **无依赖**：独立场景、地点、背景、透明素材或独立覆盖层。可完整并行制作。

并行前先锁定共享母场景的接口。每个分支只写唯一目录，不改 `timeline.json`、共享源文件和已通过镜头，并明确自己的输入参数与输出。分支只交付接触表或预览，不建立单独报告体系。

## 尾帧差分

对强依赖镜头，比较“上一镜通过尾帧”和“本镜首帧”，只保留四类施工范围：

| 类别 | 处理 |
| --- | --- |
| 延续 | 直接复用，不重画 |
| 变形 | 在原元素上改变几何或状态 |
| 新增 | 本镜新建 |
| 消失 | 淡出、移出或降级，不删除重来 |

连续形变镜头的“新增”应很少。若主体被整体替换，通常会出现叠层、闪现或风格断裂。

## 共享母场景

同组镜头共用一套主体渲染器、1920×1080 舞台、主时钟、CameraRig、背景系统和资产加载器。镜头主要是状态与时间参数，不要为每镜复制 HTML、依赖库、素材和整套场景树。

允许新增元素、旧元素变形和边界重算；不允许重画整个主体、用新场景覆盖旧场景，或在集成时顺手重构已通过画面。

总时间线是真组合：镜头是同一舞台在不同时间激活的图层与状态，不是 iframe 或页面切换。`/index.html` 必须从 0 秒独立初始化；调试入口也必须能独立初始化。

## 精简交接

`HANDOFF.md` 是当前状态，不是工作日志，建议少于 100 行，只保留：

1. 当前镜头/分组与下一步。
2. 已锁定的镜头、主体、素材和接口。
3. 当前使用的文件与参数入口。
4. 尚未解决的问题。
5. 已否决方案及一句理由。

旧过程、完整提示词、工具输出和报告不进入交接。新对话只读这份当前状态、相关故事板和当前施工文件。
