# `/goal` 导演执行约束

本文件只在用户实际用 `/goal` 启动或恢复目标时读取。它不是普通镜头制作的必读文件。

## 核心原则

`/goal` 表示持续推进一个明确结果，不表示无限运行、无限派单或无限验证。导演的职责是缩短交付路径，让用户尽快看到可判断的画面。

对视频任务，只有用户能判断场景画面是否通过以及应如何校准。导演和执行会话都没有画面验收权，不得用自己的目视结论、审计数量、命令数量、哈希一致性或 `check` 结果代替用户确认。

## 收到大目标时

用户写“把镜头做好并给我预览”时，把它理解为最终目标，不要理解成可以一次性自动跑完全部阶段。

导演先把大目标拆成带用户关口的阶段：

1. 规划镜头如何实现；
2. 给执行会话一份只做场景的提示词；
3. 把场景画面交给用户验收和校准；
4. 只有用户明确说场景通过或可以做动画，才给同一执行会话完整动画提示词；
5. 动画完成后启动可拖动预览，只返回视频预览链接给用户继续判断。

任何 `/goal` 都不得跳过第 3 步。到达用户关口时，停止当前阶段并等待用户，不得以“目标要求持续完成”为由自行进入动画、整合或最终验收。

导演的实现规划至少写清：镜头要表达什么、主体与背景如何构成、准备用什么表示方式、关键画面状态、动画阶段设想、允许修改目录、本阶段交付物和停止点。规划服务于执行提示词，不写成分析报告。

## 派单结构

- 一个镜头只交给一个长期执行会话负责，避免多个会话重复阅读、重复诊断和相互覆盖。
- 独立镜头最多按实际依赖并行；不要再派审计、复核、自检、证据整理或“第二导演”会话。
- 导演只负责实现规划、编写执行提示词、传递用户校准意见、处理真实阻塞和切换阶段；不写代码，也不代替用户做画面判断。
- 每份派单只包含一个当前交付物、允许写入范围和明确停止点。
- 执行会话完成当前交付物后立即停止，不自行进入下一阶段。

## 正确顺序

1. 导演读取项目交接和必要 skill 一次，确认镜头目标、允许目录与已锁定内容。
2. 导演先规划实现方式，再向执行会话发出“只做场景”的提示词。不得在这份提示词中夹带完整动画、整合、正式 `check` 或最终交付。
3. 执行会话制作少量代表性关键画面后立即停止；导演原样把画面和路径交给用户，不评价“好不好”或“是否通过”。
4. 用户提出校准意见时，导演把意见转换为明确、局部、可执行的修改指令，继续交给原执行会话；不得自行发明审美修正。
5. 用户明确确认场景后，导演才发送完整镜头动画提示词。动画执行会话做完即启动一次可拖动预览并返回链接。
6. 所有相关镜头分别经用户确认后，才启动一次整合；整合只处理时间线、衔接和最终预览。

如果用户明确要求先看预览，直接启动可用预览并返回链接，不得在前面插入 `check`、批量快照或接触表。

## 禁止的冗余工作

- 不生成审计报告、自检报告、验证 JSON、过程清单或证据汇编。
- 不派 Agent 做独立视觉终审，也不由导演或执行会话宣布画面通过；视觉取舍和校准只交给用户。
- 默认不运行正式 `check`、`lint` 或其他“最终技术检查”。预览能正常打开即可交给用户；只有发生具体运行或导出故障，或者用户明确要求时，才针对该问题检查。
- 没有具体可见故障时，不做逐帧哈希、像素差、RGBA 对比、随机 seek、反向 seek、图层二分或确定性研究。
- 不重复运行 `lint`、`check`、`snapshot`、`preview` 或完整播放来证明同一结论。
- 不同时保留多个浏览器、Studio、HTTP 服务或截图进程。
- 不为寻找“更正式”的工具入口反复扫描磁盘、缓存、全局包和其他项目。
- 不重复生成多版接触表；当前阶段只保留用户需要看的那一份。
- 不让多个 Agent 重复完整阅读同一批文档后提交相同结论。
- 不因为技术检查通过就宣称镜头完成；画面需要大改时，继续优化画面，而不是增加验证。

## 阻塞处理

- 一个命令或工具失败后，只允许做一次最直接的原因定位和一次最小修正重试。
- 若仍失败，立即停止该路径，向用户说明：失败点、当前已有产物、继续所需授权或选择。
- 需要联网、安装、升级、使用项目外缓存或改变边界时，先向用户请求明确授权；等待期间不得用其他诊断填满时间。
- 连续约 10 分钟没有产生新画面、可用预览或实际代码进展时，导演必须中止当前执行并重新派单，不得让进程无反馈运行几十分钟。

## `/goal` 状态更新

只在以下情况更新用户：

- 第一批可看关键帧已完成；
- 用户需要做视觉选择；
- 出现需要用户授权的真实阻塞；
- 当前镜头或最终整合已完成。

状态消息只写结果和下一步，不复述工具调用、扫描范围、哈希、进程细节或内部验收过程。

## 允许的简单交付确认

导演不做画面验收。需要确认执行会话是否完成交付时，只能检查：

- 约定的场景文件或预览是否实际存在；
- 页面是否能够打开；
- 预览链接是否能够访问；
- 是否存在会让页面完全无法运行的直接报错。

不得进一步评价构图、颜色、材质、层次、镜头语言、运动节奏、连续性或是否需要视觉校准。把实际画面交给用户，由用户决定下一步。

## 完成标准

完成一个镜头必须由用户先确认场景画面，再确认动画结果。导演不能自行验收；技术命令成功只能说明页面可运行，不能替代用户确认。

完成整个 `/goal` 需要用户要求的镜头和整合结果均已交付；不得用“检查全部通过”替代用户实际要看的成片或预览。
